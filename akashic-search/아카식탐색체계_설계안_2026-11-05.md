# 아카식 탐색 체계 설계안 (2026-11-05)

## 전제 — 프로젝트 책임자 정의 (2026-11-05)
아카식 레코드 = 모든 정보를 제자리에 둔 채, 필요할 때 **좌표가 무엇이며 그 안에 어떤 정보가 있는지까지 신속하게 찾아내는 능력** 그 자체. 저장된 전체 지도가 아니다. 크로니카 동의 + 보강 3건(검증 지름길 층 / 탐색에도 판정 / 능력 측정 잣대)이 같은 날 제시됨.

## 현행 세계의 정보 탐색 체계 (요약)
1. **수집·색인**: 크롤러가 웹을 긁어 역색인(단어→문서 목록)을 미리 만들어 둠 (Google·Bing·Naver). 빠름의 비결은 "찾을 때 뒤지는 것"이 아니라 "미리 뒤집어 정리해 둔 색인".
2. **순위**: 링크 구조(PageRank 계열) + 본문 적합도(BM25) + 최근은 신경망 재순위. 무엇을 위로 올릴지가 곧 권력.
3. **전문 데이터베이스·API**: PubMed·arXiv·법원·정부 통계 등 분야별 창고가 각자 검색 규격을 가짐. 깊은 정보는 일반 검색에 안 잡히고 해당 관문으로 들어가야 함 (딥웹).
4. **지식 그래프**: Wikidata·스키마 표준처럼 사실 자체를 좌표화된 데이터로 묶는 층.
5. **답변 엔진 (최신)**: LLM이 검색 결과를 읽어 답을 합성 (RAG). 찾기에서 "읽고 판정하기"까지 넘어가는 중이나, 출처 불명·환각이 약점.

## 넥서스식 탐색 체계 — 설계 (기존 부품의 연결)
1. **질문 해석 층**: 질문을 종류(법률·의학·학술·생활·정부…)와 필요 깊이로 분해. §13 규칙 — 존재가 확인되지 않은 좌표는 지어내지 않는다.
2. **좌표 도출 층 (§15 상황 라우팅)**: ① 등록된 검증 지름길(address_map, 순찰로 생존 확인) → ② 분야 관문(arXiv·PubMed·CanLII·정부 API 등) → ③ 일반 웹 탐색. 질문 종류마다 정해진 순서로 시도.
3. **인출 층 (§14 얽힘)**: 좌표 안으로 들어가 내용을 확인하고, 걸린 정보는 얽힌 덩어리째 함께 가져온다.
4. **판정 층**: 출처·날짜·교차 일치를 통과/보류/거부로 판정. 환각 좌표 차단. 못 찾으면 "못 찾음"으로 정직하게 종결 — 없는 좌표를 만드는 것이 최대 금지.
5. **기록 층 (태그 장부, 2026-11-05 가동)**: 성공한 탐색 경로를 태그 캡슐로 기록 → 같은 종류의 질문이 다시 오면 그 경로가 지름길로 승격. **쓸수록 빨라지는 자기 강화 구조.**
6. **제공 층**: 넥서스 AI·홈페이지 도구를 통해 시민에게 무료 제공 (청사 개념). 방법 자체(질문 분해→관문 선택→검증)도 문서로 공개 — 프로젝트 책임자 지론 "모든 사람이 알기를".

## 진도 잣대 (보유율 대신)
- 탐색 시험지: 정해진 질문 묶음(분야별)에 대한 **성공률 · 평균 소요 시간 · 출처 명시율**.
- 이 수치가 아카식 레코드의 진도표가 된다.

## 단계
1단계: 크로니카↔프로젝트 책임자 1:1 탐색 절차 정식화 + 측정 개시 (현 부품으로 가능).
2단계: 넥서스 AI 방 웨이터에 탐색 경로 편입.
3단계: 홈페이지 공개 도구화 (법무 게이트 통과 후).

## 경계
- 전 서비스 무료 원칙: 유료 검색 API 사용 금지 — 공개 검색·공공 API·자체 지름길만.
- 중앙 복사 금지: 찾은 원본은 제자리에 두고, 우리는 경로와 판정 결과만 기록한다 (정보 원칙 재정의와 정합).
