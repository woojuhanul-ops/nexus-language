## 0. 질문과 판정 요약

질문: **AI와 컴퓨터가 패턴 언어를 알아듣는가, 효율적으로 받아들이는가.**

판정 먼저:

## 1. 방법

### 시험 A — 해석 시험

- **14B 선생(로컬 추론 서버)은 제외했다** — 점검 시점에 서버가 떠 있지 않았고(health 무응답), 기동은 무거워 지시문의 제외 조건에 해당한다. 이 사실은 한계 절에도 남긴다.
- 브리핑: 기능 기호 41개의 의미표 + 시험에 쓰는 P기호 11개의 실측 프로파일 + 문법 2문형 요약을 시스템 프롬프트로 제공(1,672토큰 — 서버 usage의 prompt_tokens 1,746과 과제분 포함해 정합). 즉 "사전을 쥐여 준 상태"의 판독 시험이다. 사전 없는 암기 시험이 아니다.
- 과제 12개: 펼치기 4(기호 문장 → 의미 서술), 짓기 4(자연어 명세 → 기호 문장), 판정 4(유효/무효 구분, 무효 2개 포함).
- 채점(전부 코드 기준): 펼치기 = 정답 핵심 필드(텐서 이름·분류·동작·수치) 포함 여부, 짓기 = `pattern_lang.py` 파싱 성공 + 구조(접두·대상·상태·동작·상대) 일치, 판정 = 유효성 일치. 대조군으로 코드 해석기의 기검증 왕복 16/16을 100% 기준으로 병기한다.

### 시험 B — 효율 시험
- 고정 메시지 20건: 패턴 사전의 실측값을 쓰는 텐서 상태 보고(상태 서술·감시·비교·판정·동기화·제외·복원 등). 같은 내용을 (a) 한국어 산문 (b) JSON (c) 패턴 문장 3포맷으로 작성.
- 측정: 포맷별 총 토큰 수와 바이트 수, 판독 정확도. 패턴·JSON은 코드 파싱 성공률, 산문은 코드 파서가 없으므로 웨이터에게 구조화 추출(JSON 회수)을 시켜 필드 정확도로 측정(20건 중 10건 표본 — 지시문이 허용한 표본 측정이며, 주방의 동일 판독도 참고로 함께 쟀다).
- 토크나이저: VM 로컬에서 Qwen3-4B GGUF의 `tokenizer.ggml` 어휘(151,936)·병합(151,387) 메타데이터로 구축한 순수 파이썬 BPE. 병합 순위 방식과 llama.cpp 방식(ID 순위)이 표본 전량에서 일치했고, 서버 usage의 prompt_tokens와도 정합했다(브리핑 실측 1,672 + 과제 ≈ 1,746).
- **판정 기준**: 절감률만으로 판정하지 않는다. 판독 정확도가 함께 서야 하며, 빠른데 틀리면 실패로 기록한다.

## 5. 최종 판정 — 이 언어는 어느 층에서 사는가

1. **코드 층: 산다 (확정).** 파싱·왕복·판정이 결정적으로 100%이고, 토큰은 산문의 1/3, JSON의 1/5이다. 기계 간 상태 보고·기록·감시의 1차 포맷으로 쓸 자격을 측정으로 얻었다.
2. **모델 층: 아직 직접 판독 구간을 열 단계가 아니다.** 브리핑을 줘도 짓기·판정에서 형식 이탈과 편향이 나왔다. 모델이 패턴 언어를 다뤄야 하는 자리에서는 코드 층이 풀어쓰기로 변환해 건네는 현행 방식(문법 정본 §9 게이트 태도)을 유지하는 것이 측정 결과에 부합한다. 단, 웨이터의 판정 4/4·짓기 3/4처럼 부분적으로 통하는 구간이 있어, 게이트를 통과할 후보 구간은 존재한다.
3. **사람·산문 층: 기계 판독용으로는 부적합.** 산문은 사람이 읽기에는 자연스럽지만 기계가 다시 구조화할 때 절반 가까이 새는 것으로 측정됐다. 상태 보고의 기계 전달은 산문이 아니라 코드 포맷(패턴 또는 JSON)이 맡아야 한다.
